# 招标抓取缺失项目修复方案

## 问题概述

对比飞书（本程序110条，去重后仅约5个独立项目）与腾讯文档（另一程序186条），缺失项目根因四类：

1. **平台覆盖不全**（72%，134条）— 未抓取中招联合、华电/华能/国电投、中交采等央企自建采购平台
2. **chinabidding 分页失效**（26%，48条）— 服务器3页后返回第3页重复内容，"连续空页中断"永远不会触发
3. **关键词缺失 + LLM误删**（~1%）— 缺少党建/干部/销售/内控等关键词；Screener误判工程建设，Extractor误删采购公告
4. **飞书去重严重不足**（数据质量问题）— 110条写入数据去重后仅约5个独立项目，同一项目被38个关键词反复命中、反复写入

### 缺失分布详情

| 缺失来源 | 条数 | 占比 | 说明 |
|----------|------|------|------|
| 未覆盖平台（中招联合等） | 134 | 72% | 央企自建采购平台 |
| chinabidding 分页失效 | 48 | 26% | 已覆盖平台中92%的缺失来自此 |
| 联通过滤遗漏 | 3 | 1% | 广东联通校招培训等被过滤 |
| 移动搜索类型不全 | 1 | <1% | 咪咕数媒内宣项目类型未覆盖 |
| SGCC/Tower 返回0条 | 待定 | 待定 | 另一程序从铁塔有数据，说明平台有匹配项目 |

### 已覆盖平台中 chinabidding 缺失占比

在已覆盖平台的52条缺失中，chinabidding 占48条（92%）。这是**最紧急的技术瓶颈**。

### 0.1 飞书写入前强制去重

**问题**：同一项目被38个关键词反复命中、反复写入飞书，110条数据去重后仅约5个独立项目。

**方案**：在 `src/output/feishu_sheet.py` 的 `create_records` 方法中，写入前基于 URL 去重。

```python
def create_records(self, records: list[dict], insert_at_top: bool = True) -> bool:
    if not records:
        return True

    # 去重：基于项目URL（项目名称中的link字段）
    seen_urls = set()
    unique_records = []
    for r in records:
        name_field = r.get("项目名称", "")
        url = ""
        if isinstance(name_field, dict):
            url = name_field.get("link", "")
        if url and url in seen_urls:
            logger.info(f"跳过重复项目: {name_field.get('text', '')[:40]}")
            continue
        if url:
            seen_urls.add(url)
        unique_records.append(r)

    records = unique_records
    logger.info(f"去重后剩余 {len(records)} 条（原始 {len(records) + 跳过数} 条）")
    # ... 后续写入逻辑不变
```

同时在 `src/processor/dedup.py` 中启用全局去重（当前已跳过）：
- 基于项目标题前20字符 + 招标单位做去重
- 维护 `seen.json` 中的已写入项目集合

## 第二阶段：chinabidding 分页失效修复（P1 最高优先级）

> 预计耗时：1.5小时，解决已覆盖平台92%的缺失

### 2.1 问题分析

**现状**：chinabidding 搜索第3页后 page 参数被服务器忽略，始终返回第3页内容。
**错误假设**：之前的"连续空页中断"策略无效——因为第4页不是空页，而是第3页的重复内容。
**影响**：关键词"绩效""培训"等高频词搜索结果有几十页，我们只能拿到前3页（约60条）。

### 2.2 方案A：按关键词独立搜索 + 结果去重（推荐）

当前逻辑是所有38个关键词一起搜，一个关键词的高频结果会占用大量页数。
改为**每个关键词独立搜索，每个关键词只取前3页**，最后全局去重：

```python
# src/scraper/chinabidding.py 修改
def _do_search(self, fetcher, keyword, category):
    """每个关键词独立搜索，最多3页"""
    all_items = []
    for page in range(1, 4):  # 只取3页
        items = self._search_page(fetcher, keyword, page)
        if not items:
            break
        all_items.extend(items)
    return all_items
```

预期效果：38个关键词 × 3页 × ~20条/页 = ~2280条原始结果，去重后约200-400条，
远多于当前的83条。

### 2.3 方案B：利用搜索结果时间排序过滤

chinabidding 前几页是最新的结果。在方案A基础上，解析每条结果的发布日期：
- 只保留最近7天的项目
- 跳过已过期的旧项目

```python
def _filter_by_date(self, items, days=7):
    """过滤7天前的项目"""
    cutoff = datetime.now() - timedelta(days=days)
    return [i for i in items if i.get('publish_date', cutoff) >= cutoff]
```

### 2.4 方案C：exclude_words 减少无关结果

在搜索时附加排除词，减少每个关键词的命中数，让3页覆盖更多目标项目：

```
搜索URL: /search/searchzbgg?keywords=绩效&exclude_words=工程,施工,监理,设备
```

### 2.5 方案选择

**推荐方案A + B组合**：按关键词独立搜索 + 日期过滤。方案C作为补充。
